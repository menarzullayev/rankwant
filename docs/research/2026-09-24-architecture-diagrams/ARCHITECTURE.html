Daraja 0 — kontekst

Tizim kim bilan gaplashadi

RankWant — bitta HTTPS sayt ortidagi modular monolit. Tashqi dunyo uchun u rankwant.uz; ochiq port yo'q, hamma kirish Cloudflare Tunnel orqali. Tizim to'rt xil foydalanuvchi va uchta tashqi xizmat bilan gaplashadi.

Tashqi aktorlar → bitta HTTPS kirish nuqtasi. Tashqi xizmatlar faqat API qatlamidan chaqiriladi; judge ularga umuman chiqmaydi.

Web kanali

Session cookie (httpOnly, Redis backend). Brauzer ham, SSR ham bir xil API'ga boradi.

API / bot kanali

Personal Access Token rw_…, bazada SHA-256; scope: read, submit, contest:manage.

Himoya qatlami

Chegara faqat loopback: nashr etilgan ikki port ham 127.0.0.1 (api:8301, web:8300).

Asosiy oqim

Submit → verdikt → reyting

Platformaning yuragi. Uchta qoida butun zanjirni belgilaydi: urinish avval bazaga yoziladi, judge bazani ko'rmaydi, va katalogda yo'q verdikt bazaga tushmaydi. NFR maqsadi: Attempt.created_at → judged_at orasida p50 < 5 s, p95 < 15 s.

Sakkiz qadamli zanjir. 2-qadam hal qiluvchi: urinish bazada bo'lgach, navbat yiqilishi ham, judge OOM bo'lishi ham yuborishni yo'qotmaydi — reap_stuck qutqaradi.

Har bir qadam: nima, qayerda, nega

  1. So'rov qabul qilinadi — sessiya va CSRF tekshiriladi, submit throttle (10 soniyada 1) qo'llanadi. web → judging.views · POST /api/v1/attempts/ Limit urilsa ham Attempt(RATE_LIMITED) qatori yoziladi — portlash tarixi ko'rinib turadi, 429 qaytadi.
  2. Urinish bazaga yoziladi — Attempt(status=PENDING) + Problem.attempt_count oshadi. judging.views.create → Postgres Tartib shart: navbat yiqilsa ham yuborish saqlanib qoladi. Teskarisi bo'lsa — navbatga tushib, bazaga yozilmagan ish yo'qolardi.
  3. Judge ishi quriladi va navbatga qo'yiladi — test havolalari, checker turi, til limiti ustama qiymati. judging.services.build_job → qvant_audit Test matni emas, havolasi ketadi (s3://bucket/key) — job hajmi kichik qoladi. Til ustama limiti Python kabi sekin tillarga adolat beradi.
  4. Judge navbatdan tortadi — BRPOP rankwant:judge:jobs. judge-go → Redis PULL modeli ADR-0004 ning asosi: judge hech qanday portni ochmaydi, ya'ni unga tashqaridan murojaat qilib bo'lmaydi.
  5. Kod sandboxda bajariladi — kompilyatsiya, N test, checker. judge-go · nsjail + cgroup Vaqt CPU vaqti bo'yicha o'lchanadi (wall clock emas) — yuklangan host adolatsiz TLE bermasligi uchun. cgroup preflight o'tmasa worker umuman ishga tushmaydi.
  6. Natija navbatga qaytadi — LPUSH rankwant:judge:results. judge-go → Redis Ish `attempt_id`, `custom_run_id` yoki `hack_id` bilan belgilanadi — uch xil natija egasi bir navbatda ketadi.
  7. Worker natijani o'qiydi — beat 2 soniyada drain_results chaqiradi. worker · judging.drain_results Keng shift (500 ta) ataylab: judge 66 yechim/s beradi, tor shift zaxirani yo'q qilardi. Marshrut tartibi qat'iy — hack birinchi, chunki u attempt_id=0 yuboradi.
  8. Natija yoziladi va keyingi qadam boshlanadi — katalogga qarshi tekshiruv, reyting, standings. judging.apply_result → ratings / contests Katalogda yo'q verdikt IE ga aylanadi — judge yuborgan har qanday satr bazaga tushavermaydi.

Qotib qolgan urinish

Judge ishni olib, keyin yiqilsa (deploy, OOM) ish yo'qoladi. reap_stuck (60 s) navbat bo'sh bo'lsa va urinish 5 daqiqadan oshgan bo'lsa bir marta qayta navbatga qo'yadi. Yana qotsa — DENIAL_OF_JUDGEMENT: yolg'on kutishdan halol xato yaxshi.

Custom test (P0-4)

Bir marta stdin bilan ishga tushirish: mode=custom, chiqish kutilgan javob bilan solishtirilmaydi. Konservativ limitlar (5 s / 256 MB), reytingga umuman ta'sir qilmaydi, lekin bir xil throttle ostida turadi.

Kaskad

Verdikt yozilgandan keyin nima bo'ladi

apply_result oxirida bitta hodisa butun platformaga tarqaladi. Tartib ataylab belgilangan: zaif tomon (Qvant, bildirishnoma, yutuq) yiqilsa ham baholash va reyting saqlanib qolishi kerak.

Kaskad uch tarmoqqa bo'linadi: statistika keshi, AC zanjiri va contest standings. Qizil punktir — rejudge yo'li.

Birinchi AC — qat'iy tartib

  • Yozuv yaratiladi — takroriy AC shu yerda uziladi.
  • Sanoq oshadi — yashirin contest masalasi public sanqqa kirmaydi.
  • recalc_skills — joriy qiyinliklardan qayta hisoblanadi.
  • Shundan keyin Qvant — reyting yozuvi Qvant xatosidan qat'i nazar saqlanadi.

Rejudge AC ni bekor qilsa

  • Boshqa AC bor bo'lsa — yozuv o'sha urinishga ko'chadi, reyting tegilmaydi.
  • Yo'q bo'lsa — yozuv o'chadi, sanoq noldan pastga tushmaydi.
  • Skills qayta hisoblanadi, sabab RECALCULATION.
  • Qvant kun sharti bo'yicha qaytariladi (attempt havolasi bilan emas).
Hisoblagich va qatorlar ajralib ketishi mumkin. solved_count kodni chetlab yo'qolsa (kaskad o'chirish, import, qo'lda tuzatish) — buni tiklash uchun alohida vosita bor: python manage.py recount_problems.
Chegara shartnomasi

Judge bilan aloqa — ikki navbat, nol to'g'ridan-to'g'ri chaqiruv

Butun integratsiya ikki Redis ro'yxatida tugun. Judge hech qachon API'ga so'rov yubormaydi va API ham unga yubormaydi — ikkisi ham navbatga yozib, navbatdan o'qiydi. Bu services/bakeoff/protocol.md da qulflangan shartnoma.

To'rt yo'nalish, ikki kalit. job_id — yagona bog'lovchi identifikator; judge natijada uni aynan qaytaradi.

Ikki shakl — butun chegara shu ikkovidan iborat

JudgeJob — API → judge

  • job_id, attempt_id, hack_id, hack_stage — marshrut
  • language — argv ro'yxati (compile, run, source_file)
  • limits — compile/time/memory/output/processes
  • tests[] — input_ref / output_ref (S3 havolasi)
  • checker — standard / special / scorer / interactive
  • mode — acm (birinchi xatoda to'xtaydi) · ioi · custom

Result — judge → API

  • verdict — 20 kodli katalogdan
  • score, time_ms, memory_kb, failed_test_index
  • compile_output — stdout + stderr, 64 KB gacha
  • per_test[] — test bo'yicha verdikt va resurs
  • judge_meta — queue_wait_ms, sandbox_setup_ms, total_ms
Vaqt o'lchash — adolat masalasi. time_ms — CPU vaqti (user + sys), wall clock emas: yuklangan host aks holda adolatsiz TLE beradi. IDLENESS — CPU kam, lekin wall clock oshgan (interactive'da deadlock). memory_kb — peak RSS. Uch o'lchov xato bo'lsa → adolatsiz verdikt → reyting ishonchsiz.

Hack marshruti — bitta oqim, uchta bosqich

Hack dvigateli judge ichida emas — API'da. Judge faqat hack_id va hack_stage ni aynan qaytaradi, talqin qilmaydi. Bitta hack uchta alohida ish ochadi va javoblar navbatdan istalgan tartibda kelishi mumkin — shuning uchun marshrut belgilari shart.

O'zgarmas qoidalar

Arxitekturani ushlab turadigan chegaralar

Bu qoidalar kodda majburiy — izoh emas, tekshiruv. Ular buzilsa tizim sekin yoki noto'g'ri ishlaydi, lekin xato bermaydi; shuning uchun har biri o'lchov bilan qabul qilingan va tools/check_decisions.py har PR'da qatorlarni tekshiradi.

Judge hech narsani bilmaydi

  • DATABASE_URL berilsa process exit 1 — jim ishlamaydi.
  • Kiruvchi port yo'q: PULL modeli navbat orqali.
  • Tashqi internet yo'q; faqat Redis va S3.
  • cgroup preflight o'tmasa worker umuman ishga tushmaydi.

Balans to'g'ridan-to'g'ri yozilmaydi

  • Yagona yo'l — qvant.ledger (credit/debit).
  • Qulf (select_for_update) hisobdan oldin olinadi — aks holda parallel mukofotlar bir-birini ko'rmaydi.
  • Kunlik emissiya shifti; streak va admin ozod.
  • Balans manfiyga tushmaydi — qaytarish mavjud balansgacha cheklanadi.

Chegara faqat loopback

  • Nashr etilgan ikki port ham 127.0.0.1: api:8301, web:8300.
  • Judge, postgres, redis, minio — port e'lon qilmaydi.
  • Overlay ports: !reset [] bilan bazaviy portni o'chiradi — bazaviy faylni yolg'iz o'qish noto'g'ri xulosa beradi.

Kesh — ixtiyoriy qatlam

  • Kesh yiqilsa sahifa sekinlashadi, o'chmaydi.
  • Profil statistikasi versiya bilan eskirtiriladi — eski yozuv muddati bilan ketadi.
  • Invalidatsiya on_commit da — parallel so'rov eski ma'lumotni yangi versiya ostida keshlab qo'ymasin.
Ma'lum ochiq chetlanish. Hozirgi preview'da judge, Postgres va Redis bitta mashinada — ya'ni ajratish host chegarasi emas, konteyner chegarasi. ADR-0004 ning «judge host API/DB bilan bir serverda emas» sharti maqsad topologiyasida bajariladi, bugun emas. Bu — qabul qilingan risk, threat model'da yozilgan.

Deploy topologiyasi — hozir va maqsad

Hozir — bitta mashina

Bitta host, ochiq port yo'q, Cloudflare Tunnel. Django admin tunnel'dan chiqarilmagan — faqat 127.0.0.1:8301/admin/. docker-compose.public.yml bilan restart: unless-stopped va ichki portlarni tashqariga chiqarmaslik.

Maqsad — to'rt host

app (API + worker) · web · judge×N · data (Postgres, Redis). Xavfsizlik chegarasidan kelib chiqadi: judge hostda kiruvchi port yo'q, ya'ni uni alohida joylashtirish mantiqan ham, operatsion jihatdan ham mumkin.
